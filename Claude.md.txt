Svach AI HQ

Project Overview

Svach AI HQ is the internal operating system for Svach AI.

It is being designed as an AI-first enterprise platform that manages every aspect of the agency, including operations, clients, projects, AI agents, CRM, finance, marketing, documents, analytics, knowledge management, and future client portals.

This is a long-term product intended to scale into a complete AI Operating System.

Product Philosophy

Svach AI HQ is NOT:

A CRM
A project management tool
A generic dashboard

Every feature should strengthen the ecosystem rather than exist in isolation.

AI Philosophy

AI should assist the user, not replace decision-making.

The platform will eventually include:

Operations Orchestration Agent (OOA)
Sales Agent
Marketing Agent
CRM Agent
Finance Agent
Knowledge Agent
Support Agent

OOA will coordinate all specialist agents.

OOA is the only proactive orchestrating agent. It is developed/deployed separately on
Hermes, a dedicated external runtime — not part of the Svach AI HQ codebase. Claude
Code builds Svach AI HQ as the control plane (dashboard, approvals, audit trail, and
the API boundary to Hermes) and does not implement OOA's reasoning engine inside HQ.
All other specialist agents (Sales, CRM/Nexus, Delivery, Finance, Marketing, Support)
are reactive — they act only when delegated to, explicitly requested, or triggered by
an event or workflow, never running their own proactive monitoring loop. See
/docs/DECISION_LOG.md §10 and /docs/AI_ARCHITECTURE.md for the full architecture.

Security

RLS is enabled on every table from day one, no exceptions — including lookup tables
and tables unused in V1. External services (Hermes, future integrations) always
authenticate with a purpose-built credential scoped to one capability — never a
general Supabase service-role key. See /docs/SECURITY_STANDARDS.md and
/docs/SECURITY_POLICY.md.
